## Scope

For approved, clear implementation work that needs no clarification. Governs execution flow, not code quality, API contracts, or documentation approval.

## Required behavior

- Start as soon as requirements are clear and no blocking ambiguity remains. Keep implementation focused, minimal, and production-ready.
- Prefer direct edits to prolonged analysis or exploratory discussion; run the smallest check that verifies intended behavior.
- Stop only if a required fact is missing, ambiguous, or too high-risk to proceed without confirmation.

## Do not

- Avoid speculative changes, broad refactors, unrelated cleanup, repetitive status/explanations, unnecessary alternatives, and guesses about requirements, APIs, or intent.

## Execution standard

After confirmation, act without delay, follow the task and project conventions, and favor timely completion with evidence over prolonged optimization.
