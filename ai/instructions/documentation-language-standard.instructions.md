## Scope

Applies repository-wide to documentation, comments, docstrings, commit messages, and generated code artifacts, regardless of the user's language. Covers language and writing quality, not approval flow, README policy, or API contracts.

## Required behavior

- Write project documentation, inline comments, docstrings, commit messages, and repository text in English, even when the user writes another language.
- Prefer precise, unambiguous wording and consistent terminology.

## Exception

If the user explicitly requests a German chat response, the reply may be German; repository text, code comments, documentation, generated artifacts, and files must remain English.

## Do not

- Do not mix English and German in repository documentation or comments, leave ambiguous or untranslated text, or contradict the current implementation.

## Documentation quality standard

Keep wording clear, direct, and maintainable.
- Match the repository’s existing English-only conventions in every file you create or modify.
