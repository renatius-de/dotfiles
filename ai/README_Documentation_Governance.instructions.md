---
name: README and Documentation Governance
description: "Use when evaluating whether documentation or README files should be updated; require explicit approval before modifying or creating README files."
applyTo: "**"
---
- Review whether project documentation or README files need updates whenever behavior, setup steps, configuration, or project expectations change.
- Treat README changes as a deliberate, approval-gated action rather than a default side effect of code edits.
- Do not create or modify README files without explicit user confirmation.
- If documentation updates are necessary, propose the change succinctly and wait for approval before editing any README file.
- For non-README documentation, prefer small, relevant updates that stay aligned with the actual project behavior and the repository’s existing structure.
- Keep all documentation consistent with the repository’s current implementation and English-only standards.
